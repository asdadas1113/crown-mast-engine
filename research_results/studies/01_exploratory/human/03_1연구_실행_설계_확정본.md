# 1연구 실행 설계 확정본

상태: **설계 동결 / 실행 미승인**

이 문서는 Crown–Mast 1연구의 실행 설계를 고정한다. 연구 표본의 실제 생성·수집은 사용자의 별도 명시 승인 전에는 수행하지 않는다.

## 1. 연구 식별자

- 연구명: Crown–Mast 광범위 탐색 1연구
- study ID: `crown-mast-study-01-exploratory-v1`
- 성격: 탐색 연구
- 목적: 대표적인 Crown/Mast 성장 조건에서 광범위한 verified-core 조합을 비교하고, 전체 경향과 후속 정밀연구 후보를 함께 찾는다.

이 연구는 모든 계정·모든 보스·모든 성장상태에 대한 보편 규칙을 증명하지 않는다.

## 2. 고정 전투 조건

- 전투시간: 180초
- 시간축: RAID14
- baseline rotation: `opening_mast_crown_mast`
- pattern loss: OFF
- 명중 모델: 큰 단일 보스에 대한 ideal-hit
- Crown build: OL5 + SR15 고정
- Mast: Romantic Maid build: OL5 + SR15 고정
- Crown/Mast 상대 성장차: 1연구 직접 탐색축에서 제외

Crown/Mast 상대 성장 변화는 1연구 결과에서 민감성이 의심될 경우 후속 연구에서 별도 검증한다.

## 3. B1 후보

verified-core B1은 다음 4명으로 고정한다.

```text
liter
anis-star
little-mermaid
rapi-red-hood
```

`rapi-red-hood`가 B1일 때 동일 캐릭터를 Main B3에 중복 배치하지 않는다.

## 4. Main B3 후보

다음 6명으로 고정한다.

```text
rapi-red-hood
cinderella
cinderella-crystal-wave
neon-vision-eye
phantom
bready
```

현재 1연구 aggregate에서 제외되는 Main/관련 캐릭터는 다음과 같다.

```text
scarlet-black-shadow
liberalio
raven
quency-escape-queen
milk-blooming-bunny
```

이들은 모델 gate가 해소되기 전에는 1연구 승패 비율 또는 변수효과 집계에 합치지 않는다.

## 5. Secondary B3 기준점

다음 3명으로 고정한다.

```text
epinel
helm
snow-white-heavy-arms
```

역할은 각각 낮은 opportunity-cost, 중앙 실전형, 높은 opportunity-cost stress anchor다. 최종 해석에서는 이 라벨보다 실제 계산된 딜과 지분을 우선한다.

## 6. roster 수

원시 조합:

```text
4 B1 × 6 Main × 3 Secondary = 72
```

Rapi B1 + Rapi Main 중복 3개를 제외한다.

```text
72 - 3 = 69 valid rosters
```

## 7. 성장 프로필

B1/Main/Secondary는 다음 4단계 growth profile을 사용한다.

```text
g1-base5-none
g2-ol0-sr5
g3-ol0-sr15-e3-a3
g4-ol5-sr15-e4-a4-ammo3
```

### 애장품 캐릭터 규칙

애장품 캐릭터는 모든 growth profile에서 SR15를 canonical floor로 유지한다.

즉 프로필의 SR 값이 SR15 미만이어도 애장품 캐릭터는 SR15 아래로 낮추지 않는다. 다른 성장축만 해당 profile에 맞춰 변화시킨다.

이 규칙 때문에 profile ID만 저장해서는 충분하지 않다. 각 case의 최종 build 값을 manifest/scenario에 함께 저장한다.

## 8. 성장 표본 설계

4수준 3축 완전교차 64점 대신 16점 pairwise orthogonal screening을 사용한다.

프로필 인덱스를 `0..3`으로 두고:

```text
B1 = i
Main = j
Secondary = (i + j) mod 4
```

를 모든 `i, j` 조합에 적용한다.

따라서:

- B1 × Main 16조합을 정확히 한 번씩 포함
- B1 × Secondary 16조합을 정확히 한 번씩 포함
- Main × Secondary 16조합을 정확히 한 번씩 포함
- 순수한 3축 growth interaction은 완전히 식별하지 않음

1연구는 screening이므로 이 제한을 허용한다. 이상치와 sign flip은 후속 full-grid의 후보로 넘긴다.

## 9. 환경축

### DEF

```text
140
12,000
31,784
```

각각 low / representative / high sensitivity anchor다. 발생확률이나 universal boss DEF를 뜻하지 않는다.

### Core

```text
0%
100%
```

실제 명중확률이 아니라 idealized sensitivity extremes다.

### Main advantage

```text
off
on
```

`on`에서는 Main에게 실제 우월을 주는 boss element를 선택하며, 동일 속성 관계를 가진 다른 아군에도 실제 우월 규칙을 적용한다.

환경축은 완전교차한다.

```text
3 DEF × 2 core × 2 advantage = 12 conditions
```

## 10. 전체 표본 수

한 roster당:

```text
16 growth × 12 environment = 192 scenarios
```

전체:

```text
69 rosters × 192 = 13,248 scenarios
```

이 13,248개가 1연구 A1의 동결된 예상 표본 수다.

다만 실제 실행 직전에 case generator가 동일 수를 생성하는지 다시 fail-closed로 확인한다. 수가 다르면 실행하지 않는다.

## 11. 1연구에서 반드시 저장할 결과

각 case에서 최소 다음을 저장한다.

- Conventional/크크메 총딜
- Funnel/몰아주기 총딜
- 상대 변화량
- 승패 방향과 효과크기 band
- 캐릭터별 Conventional/Funnel 총딜
- Main 및 Secondary 실제 딜 지분
- roster/build/environment/timeline 식별값
- 각 캐릭터의 실제 최종 build 값
- engine/catalog/hook provenance

추가로 후속연구 선별을 위해 가능한 범위에서 다음 source 구조를 저장 또는 집계한다.

- normal
- burst
- distributed
- sequential
- sustained/시간분산형 source
- burst cycle 또는 주요 phase별 damage contribution

source 분류가 캐릭터별 구현 차이 때문에 직접 비교가 어려운 경우 원시 damage event/category를 보존하고, 해석용 통합 분류는 결과 분석 단계에서 별도로 만든다.

## 12. 후속 연구 확대 트리거

다음 항목 중 하나라도 만족하면 후속연구 후보로 기록한다.

1. 16 growth point 사이에서 winner sign flip
2. DEF 변화에 따른 sign flip
3. core 변화에 따른 sign flip
4. Main advantage 변화에 따른 sign flip
5. 상대 변화량 절대값 0.5% 이내 close-call
6. 같은 Main/Secondary 계열에서 반복되는 이상치
7. 유사 Main damage share인데 정책 반응이 크게 다른 경우
8. 특정 damage source 구조와 정책 반응이 연동되는 것으로 의심되는 경우
9. Crown/Mast 상대 성장 민감도를 별도 확인할 필요가 있는 경우

후속연구에서는 필요에 따라 64-point growth full grid, Crown/Mast 성장 sweep, source-by-source 분석, hit/spread sensitivity를 수행한다.

## 13. 재현성 및 실행 gate

실행 전 manifest에는 최소 다음이 채워져 있어야 한다.

- `study_id`
- `run_id`
- 실행 Git commit SHA
- catalog source revision + content SHA-256
- engine rule revision
- skill-hook revision/signature
- case/scenario schema version
- roster/growth/environment 정의
- 69 roster, 16 growth, 12 environment, 13,248 scenario 산술
- 실행 전 regression 검증 참조

다음 중 하나라도 불일치하면 실행하지 않는다.

- 후보군이 allowlist와 다름
- blocked actor가 aggregate에 포함됨
- 동일 actor 중복 roster가 존재함
- case ID가 중복됨
- RAID14가 아닌 timeline이 포함됨
- expected revision과 runtime revision이 다름
- non-finite 전투수치가 존재함
- burst cycle이 서로 겹침
- reload-speed ceiling gate가 깨짐
- 총 case 수가 13,248이 아님

## 14. 결과 해석 범위

1연구에서 직접 말할 수 있는 것은 다음 범위다.

> 대표적인 고정 Crown/Mast 성장 조건과 verified-core 표본에서, 다양한 성장·DEF·core·우월 조건을 탐색했을 때 크크메와 몰아주기의 상대 우세가 어떻게 분포했으며 어떤 예외가 나타났는가.

1연구만으로 다음을 확정하지 않는다.

- 모든 Crown/Mast 성장비에서도 동일한 경향
- 모든 NIKKE 캐릭터에 대한 보편 결론
- 모든 실제 Solo Raid 보스에서 동일한 결과
- Main damage share 하나만으로 최적 정책 예측 가능
- 발견된 이상치의 인과 기전
