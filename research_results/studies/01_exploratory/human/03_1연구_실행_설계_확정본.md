# 1연구 실행 설계 확정본

상태: **설계 동결 / model gate 종료 / 실행 준비 완료 / 실행 미승인**

이 문서는 Crown–Mast 1연구의 실행 설계를 고정한다. `execution_ready=true`는 모델·generator 검증상 준비 완료를 뜻하며, 연구 실행 승인을 뜻하지 않는다. 연구 표본의 실제 전투 시뮬레이션·수집은 사용자의 별도 명시 승인 전에는 수행하지 않는다.

## 1. 연구 식별자

- 연구명: Crown–Mast 광범위 탐색 1연구
- study ID: `crown-mast-study-01-exploratory-v1`
- 성격: 탐색 연구
- 목적: 대표적인 Crown/Mast 성장 조건에서 광범위한 조합을 비교하고, 전체 경향과 후속 정밀연구 후보를 함께 찾는다.

이 연구는 모든 계정·모든 보스·모든 성장상태에 대한 보편 규칙을 증명하지 않는다.

## 2. 고정 전투 조건

- 전투시간: 180초
- 시간축: RAID14
- baseline rotation: `opening_mast_crown_mast`
- pattern loss: OFF
- 명중 모델: 큰 단일 보스에 대한 ideal-hit
- Crown build: OL5 + SR15 고정
- Mast: Romantic Maid build: OL5 + SR15 고정
- Crown/Mast 상대 성장차: 1연구 직접 탐색축에서 제외

Crown/Mast 상대 성장 변화는 1연구 결과에서 민감성이 의심될 경우 후속 연구에서 별도 검증한다.

## 3. B1 후보

다음 5명으로 고정한다.

```text
liter
anis-star
moran-favorite-item
little-mermaid
rapi-red-hood
```

`moran-favorite-item`은 애장품 캐릭터이므로 모든 growth profile에서 SR15 canonical floor를 적용한다.

`rapi-red-hood`가 B1일 때 동일 캐릭터를 Main B3에 중복 배치하지 않는다.

## 4. Main B3 후보

다음 6명으로 고정한다.

```text
rapi-red-hood
scarlet-black-shadow
cinderella
cinderella-crystal-wave
liberalio
neon-vision-eye
```

`phantom`, `bready`, `raven`, `quency-escape-queen`, `milk-blooming-bunny`는 이번 1연구 Main 표본에 포함하지 않는다. 이는 구현 폐기를 의미하지 않으며 이번 연구의 표본 정의에서 제외한다는 뜻이다.

## 5. 선택 캐릭터 model gate 상태

공식 aggregate 실행 전 재검증 대상으로 지정했던 다음 세 캐릭터의 model-specific gate는 **모두 닫혔다**.

```text
moran-favorite-item
scarlet-black-shadow
liberalio
```

검증된 핵심 timing:

- Moran Favorite Item: raw reload body `60f = 1.0s`
- Scarlet: Black Shadow: raw reload body `120f = 2.0s` + fixed reload-start delay `12f = 0.2s`; 일반 공격주기 `18f charge + 26f recovery = 44f`
- Liberalio: raw reload body `120f = 2.0s` + fixed reload-start delay `12f = 0.2s`; fixed delay는 reload-speed 효과로 감소하지 않음

`WAVE_A_EXECUTION_GATED_ACTORS`는 빈 집합이며 `execution_ready=true`다.

상세 최종 검증:

```text
research_results/studies/01_exploratory/validation/05_최종_실행전_검증_2026-09-06.md
```

## 6. Secondary B3 기준점

다음 3명으로 고정한다.

```text
epinel

```

역할은 각각 낮은 opportunity-cost, 중앙 실전형, 높은 opportunity-cost stress anchor다. 최종 해석에서는 이 라벨보다 실제 계산된 딜과 지분을 우선한다.

## 7. roster 수

원시 조합:

```text
5 B1 × 6 Main × 3 Secondary = 90
```

Rapi B1 + Rapi Main 중복 3개를 제외한다.

```text
90 - 3 = 87 valid rosters
```

## 8. 성장 프로필

1연구에서는 기존 전역 4단계 growth profile 중 `g1-base5-none`을 사용하지 않는다.

B1/Main/Secondary는 다음 세 단계만 사용한다.

```text
g2-ol0-sr5
g3-ol0-sr15-e3-a3
g4-ol5-sr15-e4-a4-ammo3
```

연구상 해석은 각각 낮은 실전 성장 / 중간 성장 / 높은 성장이다.

전역 `REALISTIC_GROWTH_PROFILES`의 `g1-base5-none` 정의 자체는 다른 진단과 과거 checkpoint 호환을 위해 삭제하지 않는다. **1연구 표본에서만 제외한다.**

### 애장품 캐릭터 규칙

애장품 캐릭터는 모든 growth profile에서 SR15를 canonical floor로 유지한다.

따라서 `g2-ol0-sr5`를 선택해도 애장품 캐릭터의 실제 collection은 SR15 아래로 내려가지 않는다. 다른 성장축만 해당 profile에 맞춰 변화시킨다.

이 때문에 profile ID만 저장해서는 충분하지 않다. 각 case의 실제 최종 build 값을 manifest/scenario에 함께 저장한다.

## 9. 성장 표본 설계

세 성장 단계에 대해 B1/Main/Secondary를 **완전교차**한다.

```text
3 B1 growth × 3 Main growth × 3 Secondary growth
= 27 growth points
```

즉 가능한 3축 성장 조합을 모두 포함한다.

이전 16점 pairwise screening은 사용하지 않는다. 따라서 1연구 자체에서 다음을 직접 확인할 수 있다.

- B1 × Main 성장 상호작용
- B1 × Secondary 성장 상호작용
- Main × Secondary 성장 상호작용
- B1 × Main × Secondary의 3자 성장 상호작용

`g1-base5-none`을 제거했기 때문에 4단계 64점 완전교차보다 계산량을 줄이면서도, 현재 사용하는 세 성장 수준 안에서는 정보 손실 없는 완전교차가 된다.

## 10. 환경축

### DEF

```text
140
12,000
31,784
```

각각 low / representative / high sensitivity anchor다. 발생확률이나 universal boss DEF를 뜻하지 않는다.

### Core

```text
0%
100%
```

실제 명중확률이 아니라 idealized sensitivity extremes다.

### Main advantage

```text
off
on
```

`on`에서는 Main에게 실제 우월을 주는 boss element를 선택하며, 동일 속성 관계를 가진 다른 아군에도 실제 우월 규칙을 적용한다.

환경축은 완전교차한다.

```text
3 DEF × 2 core × 2 advantage = 12 conditions
```

## 11. 전체 표본 수

한 roster당:

```text
27 growth × 12 environment = 324 scenarios
```

전체:

```text
87 rosters × 324 = 28,188 scenarios
```

이 **28,188개**가 현재 1연구의 동결된 예상 표본 수다.

최종 실행 전 case-generation preflight에서 실제 generator가 정확히 28,188개의 고유 case ID를 생성하는 것을 확인했다. 해당 preflight는 **전투 시뮬레이션을 실행하지 않았다.**

## 12. 1연구에서 반드시 저장할 결과

각 case에서 최소 다음을 저장한다.

- Conventional/크크메 총딜
- Funnel/몰아주기 총딜
- 상대 변화량
- 승패 방향과 효과크기 band
- 캐릭터별 Conventional/Funnel 총딜
- Main 및 Secondary 실제 딜 지분
- roster/build/environment/timeline 식별값
- 각 캐릭터의 실제 최종 build 값
- engine/catalog/hook provenance

추가로 후속연구 선별을 위해 가능한 범위에서 다음 source 구조를 저장 또는 집계한다.

- normal
- burst
- distributed
- sequential
- sustained/시간분산형 source
- burst cycle 또는 주요 phase별 damage contribution

source 분류가 캐릭터별 구현 차이 때문에 직접 비교가 어려운 경우 원시 damage event/category를 보존하고, 해석용 통합 분류는 결과 분석 단계에서 별도로 만든다.

## 13. 후속 연구 확대 트리거

다음 항목 중 하나라도 만족하면 후속연구 후보로 기록한다.

1. 27 growth point 사이에서 winner sign flip
2. DEF 변화에 따른 sign flip
3. core 변화에 따른 sign flip
4. Main advantage 변화에 따른 sign flip
5. 상대 변화량 절대값 0.5% 이내 close-call
6. 같은 Main/Secondary 계열에서 반복되는 이상치
7. 유사 Main damage share인데 정책 반응이 크게 다른 경우
8. 특정 damage source 구조와 정책 반응이 연동되는 것으로 의심되는 경우
9. Crown/Mast 상대 성장 민감도를 별도 확인할 필요가 있는 경우

현재 3단계 성장축 자체는 이미 완전교차이므로 후속 연구에서 같은 축의 64점 full-grid를 반복할 필요는 없다. 필요하면 Crown/Mast 성장 sweep, 더 세밀한 성장 수준 추가, source-by-source 분석, hit/spread sensitivity를 독립적으로 수행한다.

## 14. 재현성 및 실행 gate

실행 전 manifest에는 최소 다음이 채워져 있어야 한다.

- `study_id`
- `run_id`
- 실행 Git commit SHA
- catalog source revision + content SHA-256
- engine rule revision
- skill-hook revision/signature
- case/scenario schema version
- roster/growth/environment 정의
- 87 roster, 27 growth, 12 environment, 28,188 scenario 산술
- 실행 전 regression 검증 참조
- actor model gate 검증 참조

다음 중 하나라도 불일치하면 실행하지 않는다.

- 후보군이 본 문서와 다름
- 현재 비선정 actor가 aggregate에 포함됨
- 동일 actor 중복 roster가 존재함
- `g1-base5-none`이 1연구 case에 포함됨
- case ID가 중복됨
- RAID14가 아닌 timeline이 포함됨
- expected revision과 runtime revision이 다름
- non-finite 전투수치가 존재함
- burst cycle이 서로 겹침
- reload-speed ceiling gate가 깨짐
- 총 case 수가 28,188이 아님
- `execution_ready`가 true가 아님
- actor execution gate가 다시 생김
- 사용자 명시 실행 승인이 없음

최종 preflight `34002759044`에서 모델·generator·회귀 관련 gate는 모두 통과했다. 사용자 승인 gate만 별도로 남아 있다.

## 15. 결과 해석 범위

1연구에서 직접 말할 수 있는 것은 다음 범위다.

> 대표적인 고정 Crown/Mast 성장 조건과 현재 5 B1 × 6 Main × 3 Secondary 표본에서, OL0부터 시작하는 세 단계의 B1/Main/Secondary 성장 완전교차와 다양한 DEF·core·우월 조건을 탐색했을 때 크크메와 몰아주기의 상대 우세가 어떻게 분포했으며 어떤 예외가 나타났는가.

1연구만으로 다음을 확정하지 않는다.

- 모든 Crown/Mast 성장비에서도 동일한 경향
- 모든 NIKKE 캐릭터에 대한 보편 결론
- 모든 실제 Solo Raid 보스에서 동일한 결과
- Main damage share 하나만으로 최적 정책 예측 가능
- 발견된 이상치의 인과 기전
