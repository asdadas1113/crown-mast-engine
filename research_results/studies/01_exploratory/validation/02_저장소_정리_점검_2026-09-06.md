# 저장소 정리 점검 — 2026-09-06

## 1. 목적

1연구 실행 설계를 동결하기 전에 저장소의 active branch, 임시 branch, 문서, 실행 경로를 점검하여 현재 연구와 무관한 잔여물이 새 연구에 섞이지 않도록 한다.

이 문서는 삭제 기록이 아니라 **유지 / 삭제 후보 / 보존 필요**를 구분하는 점검 기록이다.

## 6. research_results 점검

현재 최상위에는:

```text
README.md
RESEARCH_STATUS_2026-09-05.md
WAVE_A_VERIFIED_CORE_DESIGN_DRAFT.md
runs/
studies/
```

이 중 새 표준은 `studies/`다.

### `WAVE_A_VERIFIED_CORE_DESIGN_DRAFT.md`

기존 verified-core 설계의 근거가 담긴 유효한 역사 문서지만, 1연구 최종 설계가 `studies/01_exploratory/human/03_1연구_실행_설계_확정본.md`로 동결된 뒤에는 active 설계 문서 역할을 끝낸다.

판정: **내용 삭제는 하지 않고 superseded pointer로 축소**.

### `research_results/runs/`

기존 전역 run 저장 방식의 잔여 포인터다. 실제 새 연구 데이터는 각 연구의 `studies/<study>/machine/` 아래에 저장한다.

현재 `runs/`에는 새 연구 데이터가 없고 README만 존재한다.

판정: **deprecated migration pointer로 당분간 유지**.

기존 링크가 완전히 사라진 뒤 삭제할 수 있다.

### `RESEARCH_STATUS_2026-09-05.md`

9월 5일 preflight 상태를 기록한 역사적 status 문서다.

판정: **유지**.

날짜가 명확해 최신 상태 문서와 혼동 가능성이 낮고, 재검증 이후 설계가 어떻게 바뀌었는지 추적하는 데 가치가 있다.

## 7. workflow / script 잔여물

현재 active branch에는 `.github/workflows/` 디렉터리가 없으며, 임시 validation workflow는 제거돼 있다.

active root `scripts/` 디렉터리도 없다.

과거 official workflow와 실행 script는 archive 아래에만 남아 있다.

판정: **clean**.

## 8. 정리 원칙

앞으로는 다음 원칙을 사용한다.

1. 현재 연구용 문서는 `research_results/studies/<study>/` 아래에 둔다.
2. 과거 연구 또는 superseded 결과는 `archive/`에 둔다.
3. 임시 workflow는 검증 완료 뒤 branch에서 제거한다.
4. branch는 이름만 보고 삭제하지 않고 고유 commit 유무를 먼저 확인한다.
5. 현재 branch가 완전히 포함하는 검증/실험 branch는 삭제 후보로 본다.
6. historical status 문서는 날짜가 명확하면 보존한다.
7. active 설계 문서는 하나만 canonical로 지정한다.
