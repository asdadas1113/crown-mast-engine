# RAID14 패턴 대응형 Mast2 선사용 후속연구 설계 — 2026-09-01

## 상태

이 문서는 `RESEARCH_HANDOFF_V6_LEGACY_FULL.md` §25의 **12버스트 시절 패턴손실 후속연구 설계를 RAID14 기준으로 갱신한 현행 설계 문서**다.

기존 §25는 연구 아이디어의 역사적 기록으로 보존한다. 실제 구현·실험에서는 이 문서를 우선한다.

본 후속연구는 다음 두 연구와 분리한다.

```text
본 연구
- 패턴 OFF
- 현실적인 성장범위에서 크크메 vs 지속 몰아주기 비교
- 목적: 평상시 기본 회전 결정

첫 버스트 후속연구
- Crown opener vs M1 opener
- 목적: 첫 사이클 최적화와 캐릭터별 예외 확인

패턴손실 후속연구 — 이 문서
- 평상시 기본 회전은 유지
- 예정된 M3 구간에 예측 가능한 타격손실이 있을 때만 해당 묶음에서 M2를 앞당김
- 목적: 기본 회전을 깨야 할 실전 판단기준 생성
```

즉 이 연구는 기존 관습을 검증하는 단계보다 한 단계 더 나아가, **평상시 기본값을 언제 의도적으로 깨야 하는가**를 수치화하는 실전 의사결정 연구다.

---

# 1. 연구 질문

RAID14에서 M1 opener를 고정한 현재 conventional 회전은 다음 구조다.

```text
M1, C, M3 / C, C, M3 / C, C, M3 / C, C, M3 / C, M2
```

정상적인 `C,C,M3` 묶음에서 마지막 M3 Full Burst 구간에 보스의 무적·이동·저지·강제기믹 등으로 **사전에 예상 가능한 유효피해 손실**이 충분히 클 것으로 보인다면, 그 한 묶음만:

```text
C,C,M3
→
C,M2,C
```

로 바꾸는 것이 언제부터 유리한가?

변경한 묶음이 끝난 뒤에는 다시 기본 회전으로 복귀한다.

따라서 이것은:

```text
Mast를 특정 Main B3에 반복적으로 맞추는 지속 몰아주기
```

가 아니라:

```text
곧 올 M3의 실현가치가 보스 패턴 때문에 크게 훼손될 때
그 M3를 기다리지 않고 같은 묶음의 M2를 앞당겨 쓰는 일회성 패턴 대응
```

이다.

---

# 2. 현재 RAID14에서의 개입 위치

첫 M1 묶음과 마지막 2사이클 finisher는 구조가 다르므로 1차 연구에서 제외한다.

주요 개입 후보는 정상적인 `C,C,M3`가 완전히 성립하는 다음 세 묶음이다.

```text
c4~c6
c7~c9
c10~c12
```

각 위치에서 별도로:

```text
baseline: C,C,M3
pattern response: C,M2,C
```

를 비교한다.

이 세 위치를 따로 보는 이유는 Crown 15초 carryover, ammo/reload, 스킬 proc 상태 등으로 인해 **같은 3사이클 구조라도 전투 시점에 따라 임계값이 조금 달라질 수 있기 때문**이다.

결과가 세 위치에서 거의 같으면 하나의 실전 범위로 통합한다. 차이가 의미 있게 벌어지면 `초반/중반/후반 위치별 threshold` 또는 전체 범위로 제시한다.

`c13~c14`는 정상 3사이클 묶음이 아니므로 primary threshold에서 제외한다. 필요하면 terminal sensitivity로만 별도 확인한다.

첫 버스트의 Crown/M1 문제도 이 연구에 섞지 않는다. 본 연구에서는 M1 opener를 공통 고정한다.

---

# 3. 패턴손실 변수 `L`

M3가 예정된 Full Burst 구간에서 사라지는 **유효피해 비율**을:

\[
L\in[0,1]
\]

로 정의한다.

```text
L = 0.00 → 유효피해 손실 없음
L = 0.30 → 해당 구간에서 원래 들어갈 유효피해의 30% 손실
L = 0.50 → 50% 손실
L = 1.00 → 해당 구간 유효피해 전부 손실
```

중요하게, 1차 연구의 `L`은 **시간 그 자체가 아니라 피해손실률**이다.

따라서:

```text
5초를 못 때림 = 항상 L 0.50
```

으로 정의하지 않는다.

즉발 nuke, 스킬 proc, 재장전, 지속 피해 등 때문에 같은 5초라도 어느 구간이 잘리는지에 따라 실제 손실피해가 달라질 수 있다.

10초 Full Burst에 대한:

\[
t_{loss}\approx10L\ \text{seconds}
\]

환산은 **실전 설명용 근사치**로만 사용한다.

최종 연구 결과의 기본 단위는 `L*`, 즉 유효피해 손실률이다.

---

# 4. 1차 패턴 모델의 범위

1차 연구에서는 다음처럼 정의한다.

> `L`은 예정된 M3 Full Burst 시간창에서 사라지는 유효피해의 비율이며, 그 손실 자체가 탄약·차지·발사상태를 변경하지 않는 damage-only availability loss다.

즉 기본 모델은:

```text
공격 동작과 내부 무기 상태는 정상적으로 진행
해당 구간에서 일부 피해만 실현되지 않음
```

으로 본다.

이 정의는 다음을 한 변수로 추상화하기 위한 것이다.

```text
보스 무적
타격 불가능 위치 이동
저지/기믹 처리로 인한 실질 공격손실
특정 Full Burst가 사실상 비는 고정 패턴
```

반면 다음 상황은 1차 `L` 모델과 구분한다.

```text
보스 이탈 때문에 실제 사격 자체가 멈춤
강제 엄폐로 charge/reload/ammo state가 달라짐
타겟 소멸이 캐릭터별 스킬 발동상태까지 바꿈
```

이 경우에는 단순 damage reweighting이 아니라 별도의 stateful availability mask 또는 실제 패턴 모델이 필요하다.

첫 연구에서는 범위를 넓히지 않는다. `L*`가 실전 판단선으로 충분히 안정적인지 확인한 뒤 대표 표본에서만 실제 시간마스크를 검증한다.

---

# 5. 핵심 계산 — 두 번의 stateful 실행으로 `L*` 직접 계산

구형 §25에서는 `L=0→1` sweep 또는 binary search를 기본안으로 두고 설명용 근사식 `L*≈1-A/B`를 사용했다.

현재 엔진에서는 **damage-only proportional loss라는 1차 정의 아래 더 직접적인 계산이 가능하다.**

정의:

- `C0` = 패턴손실이 없을 때 baseline `C,C,M3`를 포함한 RAID14 180초 총피해
- `P0` = 같은 조건에서 해당 묶음만 `C,M2,C`로 바꾼 RAID14 180초 총피해
- `Cw` = baseline run에서 패턴 대상 M3 Full Burst 시간창에 원래 발생한 5인 총피해
- `Pw` = pattern-response run에서 **동일한 절대 시간창**에 원래 발생한 5인 총피해

uniform proportional loss `L`을 적용하면:

\[
C(L)=C_0-LC_w
\]

\[
P(L)=P_0-LP_w
\]

손익분기 조건:

\[
C(L^*)=P(L^*)
\]

따라서:

\[
\boxed{
L^*=\frac{C_0-P_0}{C_w-P_w}
}
\]

이다.

이 식은 **현재 정의한 damage-only proportional-loss 모델 내부에서는 근사가 아니라 직접 계산식**이다.

따라서 각 성장점마다 `L`을 수십 번 바꿔 엔진을 재실행할 필요가 없다.

```text
1. baseline RAID14 전체를 stateful 실행
2. 해당 묶음만 C,M2,C로 바꾼 RAID14 전체를 stateful 실행
3. 두 결과에서 같은 패턴 대상 시간창의 damage event를 합산
4. 위 식으로 L* 계산
```

Crown 지속시간, Mast stack/reset, ammo/reload, proc 등 **회전 변경이 만든 상태차이는 1·2번의 전체 stateful 실행에 이미 반영**된다.

`L`은 그 두 완성된 결과의 특정 시간창에 적용하는 외생적 피해실현률 변수다.

# 6. `L*` 판정의 예외 케이스

다음을 둔다.

\[
D_0=C_0-P_0
\]

\[
D_w=C_w-P_w
\]

일반적인 기대상황은:

```text
D0 > 0
→ 패턴이 없으면 기본 C,C,M3가 우세

Dw > 0
→ 패턴 대상 시간창에서도 C,C,M3가 더 많은 가치를 가지고 있으므로,
   그 구간이 사라질수록 baseline의 우세가 깎임
```

이때:

\[
L^*=\frac{D_0}{D_w}
\]

이고:

```text
0 < L* < 1 → 정상적인 실전 손익분기 존재
L < L*     → C,C,M3 유지
L > L*     → 그 묶음만 C,M2,C 고려
```

그 외에는 숫자를 억지로 threshold처럼 출력하지 않는다.

### Case A — `D0 <= 0`

패턴손실이 없어도 `C,M2,C`가 이미 동급 이상이다.

이 경우는 `패턴 때문에 기본값을 깨는 threshold`가 아니다. 본 연구의 일반 전제와 다른 예외 case로 표시한다.

### Case B — `D0 > 0`, `Dw <= 0`

패턴 대상 구간을 지워도 baseline 우위가 상대적으로 줄지 않는다.

현재 uniform damage-loss 모델에서는 정상적인 양의 `L*` 역전이 없다.

### Case C — `L* > 1`

대상 구간의 유효피해를 100% 잃어도 `C,M2,C`가 역전하지 못한다.

실전 가이드는 `이 종류의 패턴손실만으로는 변경 불필요`로 표시한다.

### Case D — `0 < L* < 1`

정상 threshold.

### 경계값

`Dw≈0`이면 수치적으로 불안정한 threshold를 출력하지 않고 dominance/no-crossing으로 판정한다.

# 7. 성장점 설계 — 64점 realistic grid 유지

이 후속연구도 출발점은 **실전 적용**이다.

따라서 본 연구에서 채택한 64점 realistic growth grid를 기본으로 재사용한다.

각 가변 슬롯의 성장 상태:

```text
g1-base5-none
g2-ol0-sr5
g3-ol0-sr15-e3-a3
g4-ol5-sr15-e4-a4-ammo3
```

B1 × B3-A × B3-B의 성장차를 현실적으로 넓게 포함하는 `4×4×4 = 64`점을 한 roster/boss condition의 기본 단위로 둔다.

이 설계의 목적은:

```text
ATK 한 줄이 L*를 정확히 몇 %p 바꾸는가
```

를 분석하는 것이 아니라:

```text
실제 계정에서 나타날 법한 성장격차를 넓게 넣어도
M3 패턴손실 판단선이 비슷한 범위에 모이는가?
```

를 보는 것이다.

정확한 스탯별 인과분해나 연속 crossover가 필요해지면 본 연구가 끝난 뒤 별도의 stat parameter model로 진행한다.

기존 36점 orthogonal grid는 예상 밖의 anomaly가 생겼을 때 진단용으로만 남긴다.

---

# 8. B3 조합 선정 — '동급 DPS'를 필수조건으로 두지 않음

구형 §25는 패턴손실 자체의 인과를 깨끗하게 보기 위해 **실질 DPS가 비슷한 B3 둘**을 우선 권장했다.

현재 연구 목적은 인과분해보다 **실전 판단기준**이므로 이를 필수조건으로 두지 않는다.

우선순위는:

```text
실제로 Crown + Mast와 함께 사용할 수 있는 B3 조합
실제 보스전에서 교대 B3로 채용할 이유가 있는 조합
서로 다른 Mast 반응구조를 대표하는 조합
```

이다.

대표적으로 다음 유형을 섞는다.

```text
1. B3 두 명의 기여도가 비교적 비슷한 조합
2. Main B3의 기여도가 더 큰 현실적인 조합
3. 분배딜 비중이 높은 B3가 포함된 조합
4. 필요하면 실사용 하단부 Secondary를 포함한 조합
```

극단적으로 낮은 DPS 캐릭터는 본 실전 threshold의 대표 표본으로 쓰기보다 positive-control/stress test가 필요할 때만 별도로 사용한다.

핵심은 **여러 현실적인 조합에서 L*의 범위가 얼마나 안정적인가**다.

# 9. Boss condition

기본적으로 본 연구의 realistic grid 철학을 이어간다.

우선 비교 후보:

```text
neutral
Main B3 natural elemental advantage
```

단, 실제 패턴손실 후속연구의 목적은 특정 보스 패턴에 대응하는 것이므로 최종 활용 단계에서는 실제 대상 보스의 속성조건을 그대로 넣을 수 있다.

중요한 것은 `패턴손실 L` 외의 조건을 baseline/response 두 run에서 동일하게 유지하는 것이다.

# 10. 1차 출력

각 roster / boss condition / growth point / 개입 위치마다 최소 다음을 기록한다.

```text
intervention block: c4~c6 / c7~c9 / c10~c12
C0 = baseline 180초 총피해
P0 = 해당 묶음만 C,M2,C로 변경한 180초 총피해
pattern-free delta %
Cw = baseline의 대상 M3 Full Burst 시간창 피해
Pw = response run의 동일 시간창 피해
Dw = Cw-Pw
L* 또는 no-crossing 판정
10L*초 단순 환산값(참고용)
```

집계 요약에서는:

```text
정상 threshold 존재 비율
L* 최소값
L* 중앙값
L* 최대값
필요하면 10~90 percentile
세 intervention 위치별 분포
roster별 분포
boss condition별 분포
```

를 본다.

64점은 실제 계정의 발생확률을 반영한 표본이 아니므로 **평균/중앙값을 현실의 확률적 기대값처럼 해석하지 않는다.**
목적은 현실적인 성장범위에서 판단선이 얼마나 흔들리는지 보는 robustness check다.

# 11. 2차 검증 — 실제 시간마스크

64점 전체를 프레임 단위 실제 패턴으로 반복실행하지 않는다.

먼저 §5의 `L*` 계산으로 전체 realistic grid의 범위를 저비용으로 구한다.

그 뒤 대표 성장점 몇 개만 선택해 실제 시간형 damage availability mask를 적용한다.

예:

```text
Full Burst 앞부분 3초 손실
중간 3초 손실
뒷부분 3초 손실
앞/뒤 5초 손실
실제 특정 보스의 관찰 가능한 무적·이동 패턴
```

목적은:

> `유효피해 손실률 L*`를 `대략 몇 초를 못 때리면 되는가`라는 실전 언어로 번역했을 때 오차가 허용 가능한가?

를 검증하는 것이다.

### damage-only time mask

사격/탄약/차지 상태가 정상적으로 진행되고 피해만 실현되지 않는 패턴이라면 기존 damage event의 timestamp에 mask를 적용하는 방식으로 충분하다.

### state-changing pattern

사격 자체가 멈추거나 강제엄폐 등으로 ammo/reload/charge state까지 변하면 대표 표본에 한해 별도의 stateful pattern run을 사용한다.

이 둘을 혼동하지 않는다.

# 12. 실전 가이드로의 변환

최종 결과는 소수점 단위의 과도한 정밀도보다 **판단 가능한 범위**를 우선한다.

가상의 예:

```text
64점 대부분의 L*가 0.42~0.51
실제 시간마스크 검증에서도 대략 4~6초 부근에서 전환
```

이라면 최종 가이드는:

```text
M3 구간의 절반 가까이를 날릴 것이 명확하면 그 묶음은 M2 선사용을 고려.
손실이 4~6초 경계라면 운용 차이보다 실전 변동이 클 수 있으므로 강제하지 않음.
```

처럼 표현한다.

반대로 roster별 L*가 크게 흩어지면 universal threshold를 만들지 않는다.

```text
일반 B3군
분배딜 B3군
Main-heavy 조합
```

등 실전적으로 의미 있는 조합군별 범위를 제시한다.

# 13. 이 연구에서 하지 않는 것

1차 후속연구에서는 다음을 하지 않는다.

```text
모든 B3 전수조사
모든 보스 패턴 프레임 재현
개별 계정 Actual Account Mode
ATK/우월/장탄 한 줄 단위 인과분해
정확한 Helm↔극저딜 Secondary crossover 탐색
첫 버스트 Crown/M1 연구와 결합
실측 점수에 엔진 값을 억지로 calibration
```

필요한 세부 임계점이나 인과가 생기면 본 연구 종료 후 **연속 stat parameter model**을 만들어 별도 연구한다.

그 단계에서는 예를 들어:

```text
Main damage scale
Secondary damage scale
분배딜 비중
Mast 반응도
Boss DEF
M3 effective availability
```

등을 연속 파라미터로 두고 저비용 sweep할 수 있다.

현재 단계의 목표는 그런 상세 경계보다 **실전에서 사용할 수 있는 기본 판단선**이다.

# 14. 엔진 구현 요구사항

현재 엔진에서 추가로 필요한 핵심 기능은 작다.

### 필수

```text
1. 특정 3사이클 묶음만 C,C,M3 → C,M2,C로 바꾸는 one-block rotation policy
2. Full Burst 시간창별 5인 damage event 합산
3. C0/P0/Cw/Pw에서 L* 계산
4. no-crossing / dominance 판정
5. 64점 batch runner
```

### 2차 검증용

```text
6. damage-event time mask
7. 필요 시 state-changing availability mask
```

기존 전체 RAID14 시간축과 stateful damage simulation은 그대로 사용한다.

중요: `c4~c6`만 따로 잘라 새 전투처럼 계산하지 않는다. **항상 0~180초 전체를 실행**하여 그 개입이 이후 ammo/reload/buff/proc 상태에 미치는 영향까지 포함한다.

# 15. 결과 해석 원칙

이 연구가 성공적으로 끝났을 때 목표 프레임은 다음과 같다.

```text
1. 평상시
   → 본 연구에서 검증된 기본 회전 사용.

2. 지속 몰아주기
   → 현실적인 조합에서 기본값을 대체할 근거가 있는지 본 연구 결과로 판단.

3. 특정 M3에 큰 예측 가능한 딜로스
   → 이 후속연구의 L*와 비교.
   → L이 임계범위를 명확히 넘으면 그 묶음만 C,M2,C.
   → 이후 즉시 기본 회전으로 복귀.

4. 첫 버스트
   → 별도 Crown/M1 후속연구 결과 사용.
```

최종 목표는 매 보스마다 `크크메와 크메크를 여러 번 리트라이해서 더 높은 쪽을 고르는 것`이 아니다.

> **평상시 기본값은 넓은 현실 성장범위의 계산으로 정하고, 기본값을 깨는 예외는 `예상 M3 유효피해 손실률`이라는 관찰 가능한 변수로 판단한다.**

이것이 본 패턴손실 후속연구의 실전 목적이다.
